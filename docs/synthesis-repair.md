# AI解读校验与修正循环

## 目标与使用

此前引用一处不匹配就丢弃整份AI解读。现在首次生成后运行原有确定性检查，失败则使用上一稿和具体错误修正，再次检查。每次generate默认最多2轮修正（初稿加修正共3次模型调用），成功立即结束。重启应用、重新启用模型后，更新简报和AI重新整理自动使用此流程；旧报告不会自动改写或补回以前没有保存的草稿。可能增加token和费用，不自动运行真实API评测。

## 校验范围、输入与输出

这里的检查并不是完整事实benchmark：检查JSON结构、字段限制、状态、来源ID、引文是否为对应snippet连续逐字原文。语义支持性、事实准确率和人类理解收益仍未验证；不会降低校验要求来人为达标。合法的claims=[]表示资料不足，不强迫模型生成观点。

修正仍使用同一问题、同一批证据和白名单阅读偏好，加上上一稿（最多20000字符）、安全错误码和引用错误位置/原因。Prompt位于prompts/synthesis_repair.md，草稿只作为数据，禁用工具，不新增检索或发送整份私人档案。每轮仅携带上一稿，不累积完整修正历史。全局上下文/请求次数预算继续生效，不自动扩大。SynthesisService(max_repairs=0)可关闭修正，范围0–2。

Report.knowledge_payload.validation_attempts保留有界草稿、轮次、passed、error及可用的location/reason；草稿超过20000字符仅保留前20000并标记truncated。由原报告存储按当前账号私有保存，不提交Git，不在正式正文或诊断框直接展示未校验自由文本。通过后只用有效知识对象渲染。用户可在检索详情看到轮数及失败原因，任务状态显示正在修正几轮。

metrics累计model_calls、input_characters、model_output_characters，并新增repair_calls和validation_passed。逻辑调用数与HTTP网关重试次数不同，不能冒充真实token用量。通过校验不等于事实正确，仍保留semantic_verification=unverified。

## 终止与错误

达到修正次数后保存失败草稿和validation_repair_exhausted，明确仍未通过，来源摘录仅作为可读兜底，不能冒充AI结论。网络失败、预算不足不再启动额外修正循环；已有草稿仍随报告保存。取消传播到任务层，不继续发送请求；取消导致任务未保存时，不能保证草稿已持久化。HTTP网关恢复仍受独立上限约束。显式compare最多3种策略×3次=9次逻辑调用，调用方若限制更小以调用方预算为准，不自动增加预算。

## 验证

离线序列模型覆盖引文错误后成功、不同错误连续修正、全部失败有限终止、保留草稿但不渲染无效内容、网络失败不扩散调用、取消和可关闭修正。原有12个合成案例/36个策略回放继续执行，仅为契约回归，不是线上效果benchmark。

本次项目Python3.11 compileall通过，完整334项测试通过；未发送真实API请求。原有毫秒级时限测试改用可控时钟，避免Windows计时粒度导致不稳定，不放松有限时调用的断言。
