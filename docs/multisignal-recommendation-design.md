# 多信号推荐、三栏分发与多兴趣向量画像（设计提案）

状态：比较性研究提案。赞踩/打开、四指标与三栏的当前真实接口以[四信号推荐](multisignal-ranking.md)为准；固定大类、本地embedding多槽和锚定反馈更新已实现，实际公式以[分层语义画像](semantic-interest-profile.md)为准。本文其余候选算法仍为待实验初值，不是论文最佳参数或当前代码；训练式QKV、平台热搜适配器尚未实现。

## 1. 产品目标与交互

将用户提出的信号拆为四个内容指标：关联性R、可信度C、重要性I、热度H。点赞/点踩和原文打开是更新R的观测，不再与R作为平行特征重复加分。新鲜度F、来源可见性、隐私和事实核验状态作为边界或单独因素。

每条新闻卡片紧邻短解读显示“👍 有帮助 / 👎 没帮助”，两者互斥，再点一次撤回；刷新、重新生成报告不重复记票。点击原文按钮记一次原文打开事件，不额外要求用户操作。原有1—5分不删除，但从日常主操作退居历史兼容；不把旧星级自动转换为新点赞标签。现有明确拓展方向反馈保留历史，后续迁移需按语义区分，不能和所有新闻有用评价直接混为一种标签。

“阅读全文”指打开原网站，不是展开AI解读。只记录用户主动点击与系统接受打开动作，不把后台抓取、重试、链接预览、Agent自动操作算成点击，也不声称浏览器加载成功或全文已阅读；付费墙仍可能存在。程序不能凭离开窗口时间推断外部网页停留或实际阅读时长。

点击代表较弱的好奇/阅读意愿，点赞代表较强的主观有用反馈，二者都不是事实正确证明。点踩也可能因为解读太浅、重复或文风，所以默认只作局部、弱化的负反馈，不能一次排除整个领域。用户愿意解释时，可在既有研究对话中补充原因，不增加必填表单。涉及来源失实的对话只登记待核查问题，不凭不喜欢自动降低来源可信度。

## 2. 三栏与最终推荐分

先获得同尺度0—1且带置信/覆盖信息的R/C/I/H，再按栏目计算分数，展示可乘100。初始权重：

| 栏目 | R关联性 | C可信度 | I重要性 | H热度 |
|---|---:|---:|---:|---:|
| 个人推荐 | 0.75 | 0.15 | 0.07 | 0.03 |
| 大事件 | 0.05 | 0.25 | 0.65 | 0.05 |
| 今日热榜 | 0.05 | 0.20 | 0.10 | 0.65 |

`Score(section,u,e)=100×FreshnessFactor(e)×Σ w(section,k)×Feature(k,u,e)`。

来源可见性、重复事件、明确排除和核验状态在计算前检查，不作为可以被热度抵消的小扣分。已被证据证伪的具体主张不因高热度成为正式事实推送；如果是在报道“谣言流传/辟谣”这个事件，应明确改变事件对象，而不是删除真实的辟谣新闻。来源缺少核验、存在冲突的重大线索可单独标待核实，不能包装成确认事实。

FreshnessFactor可从0.7+0.3F起步，但日期不明不伪造F；今天窗口仍严格依据发布时间。衰减速度按内容类型区分，突发新闻小时级、产品动态天级、论文周级，不能让高价值论文用同一种小时热度规则过期。正常化/缺失值策略必须版本化，同一份报表不混用不同尺度。

大事件和今日热榜的低R权重允许跨兴趣报道，主要由各自指标决定，不以个人兴趣门槛先剔除。个人推荐只有少量重要性补充，重大事件优先放在独立栏，避免固定挤占研究新闻。栏目权重默认由产品规则确定，不自动以提高点击为目标调整“大事件”的新闻价值目标。后续高级设置可提供受约束的权重预设，不先暴露十几个难懂滑块。

用户已设置的最大数量N建议先作为三栏去重后的总解读预算，避免隐式变成3N并增加费用。初始可按6:2:2分配；高重要性事件不足时留空或将空位还给个人栏，不用低质量新闻凑数。今后可另设各栏数量，但应明确总预算上限与费用确认。三栏是不同推荐目标，不是同一新闻库按UI过滤三遍。

## 3. 关联性R：语义匹配与行为分开建模

R应解释为“针对该用户当前任务，内容可能有用的估计”，不是点击概率。冷启动先复用现有AI兴趣分和用户明确描述；接入向量后加入多槽语义匹配。初始融合可取：

```text
R = (1-g)×S + g×(0.85U + 0.15O)
g = min(0.5, n_eff / (n_eff + 20))
```

S为校准后的语义/当前AI关联性，U为明确点赞有用倾向，O为相对基线校正的原文打开倾向。n_eff按有效反馈算，不按文章总数；可从显式反馈权重1、仅点击权重0.1起步。冷启动g=0，没有行为数据不假装已有统计个性化。融合初值只用于实验，不保证适合所有用户。

点击倾向必须按栏目、位置、可见机会和标题类型校正，不能拿高位置原始CTR与底部新闻比较。可先按槽/栏目/位置分桶，用带先验的点击率估计，再与同桶基线比较；样本少显示低置信度。未点可以作为“有曝光机会但没有发生打开”的统计观测，**不是**“用户不喜欢”的负标签，不触发向量排斥。行为数据不足时O保持中性，不能将未知当0分。

单个事件对向量的最终反馈取互斥状态：点赞+1，点踩为负向证据（初始更新强度可设0.3），没有投票但主动打开+0.1，未操作不更新。点赞后不再叠加同次点击奖励；先点击后点踩要替换该次训练样本并重算，而不是先加0.1再永久留下错误正反馈。点击日志仍保留实际操作用于计数。

所有新闻都可反馈，不再只学习当前代码的探索位置。核心推荐也需要显式训练数据；探索来源、概率和位置仍单独记录。重复点击可显示操作次数，但训练按账号/事件/会话去重并限额，不能用刷新或多次打开无限放大兴趣。同一事件不同媒体报道也应合并训练权重，除非用户明确是在比较报道质量。

“大事件”的一次战争报道点击不直接改变长期学术/求职兴趣；将section作为上下文，并将偶发公共关切先放入短期兴趣状态。新增长期领域仍须用户明确说明/确认。聊天中的“我最近转向后训练”是强语义约束，通过既有档案候选确认；“这个解读太AI味”更新表达，不移动主题向量。

## 4. 可信度C：来源先验加具体证据，而不是官网固定满分

需要区分来源信誉、这条报道的证据充分度、具体主张的核验状态；C是参考分，不标为事实为真的概率。可从下式试验：

`C = clip(0.35×来源/领域先验 + 0.35×可追溯证据 + 0.20×独立交叉核验 + 0.10×纠错记录 − 未解决冲突扣分)`。

每项有观测依据与coverage。未知不补成“已核验”；只有官网身份而没有具体证据时，不能用高先验把整体抬成高置信结论。早期缺少纠错历史，使用保守先验并显示不确定性，不虚构历史正确率。

- 官网对“我们发布某产品、条款写了什么”是一手来源，但“我们的模型全行业最好”还需独立评测。
- 论坛对未经证实的宏观传闻应谨慎；带版本、复现步骤、日志/代码的技术故障报告则可能是有价值的一手证据。
- 预印本、同行评审论文、新闻报道、观点评论分开标记；不能仅凭arXiv或期刊域名判断所有结论都成立。
- 多站转载同一通讯稿/匿名爆料不是多份独立证据；纠错和冲突应按主张/事件溯源。

用户点赞/点踩首先影响R，不直接给C提供真假标签。来源可信度只能由可核查证据、明确纠错与适当人工/独立评审更新。高热度不能买过证据门槛，可信度不随用户喜欢而提高，防止强化确认偏误。

## 5. 重要性I：影响范围与跨领域传导

初始rubric可取影响人群0.30、基础设施/经济/安全冲击0.25、跨行业范围0.20、行动时效0.15、长期结构改变0.10。每项0—1并带依据、affected_domains与不确定性；它们是新闻价值维度，不是把五项交给模型自由联想。

假设某航运通道因冲突中断，事件标签不仅有国际政治，还可有已被材料支持的航运/能源/供应链影响。对于金融用户，大事件栏可解释已观察影响及尚待确认的传导路径。不能把“可能影响油价”写成“必然上涨”，也不能以此产生未授权交易建议。

不按热度代替重要性：基础设施漏洞可能少人讨论却影响很广，娱乐热点可能很热但不具同等公共影响。实际金额、人数缺失时保持未知；模型不可为了补齐rubric编数字。先用每事件一次有界结构化评估，不为每个用户重复调用重要性模型。

## 6. 热度H：真实关注的多源观测

H是“当前可观测渠道中的关注程度”，不是全网绝对热度。建议按事件而非单篇文章计算，分三个信号：独立来源覆盖（初始0.45）、接入平台的可验证榜单/互动（0.35）、近期关注增速（0.20）。这些比例仅为初值。

将报道归并为同一具体事件，再剔除同文转载、通讯社分发、同组织多个域名；不能把同公司不同事件合并成一个热榜事件。跨源归并可复用现有事件索引作候选，但需要实体+动作+对象+时间和证据支持，向量接近只是候选发现，不是同事件判定。

平台的排名/评论/赞/浏览量各自做log变换或同平台同时间窗分位归一化，再融合，不直接相加微博排名、论坛赞和论文引用量。关注加速度要有两个真实快照；新接入渠道没有历史时加速度未知，不能用刚抓到的数量假装暴涨。去除垃圾/疑似操纵信号并降低置信，但不把某网站名称直接判为刷量。

当前项目没有微博热搜、X/Instagram互动指标或全网监测，后续是否接入取决于实际可用的合法接口及访问条件。只接RSS时可显示“多源报道热度”；拿不到平台指标不得标“微博热度”。先提供覆盖维度、数据时间和缺失提示；不要自动给未知分项按0算、也不要只重归一剩余项就伪装成与完整H可比的数值。不同观测类型分桶/校准后比较，覆盖差时单列或降置信。个人的原文点击只用于R，不偷偷汇总私人行为作为公共H。

报道源数量用于H，不自动提供C核验：只有不同独立证据链才能增加交叉核验信号。多家媒体共同引用同一未核实说法，可能说明关注度高，但不能据此宣布说法为真。

## 7. 用户画像：n个可解释兴趣槽，不是训练n个语言token

用户设想可借鉴多兴趣表示，但不应将用户反馈直接替换Transformer前向attention。Transformer的attention负责根据Q/K的匹配聚合V，反馈是外部监督信号，决定之后如何调整表示/偏好，不是同一种对象。

建议保持一个冻结的多语种embedding空间，为每个已确认细分兴趣建立一个槽。n先由活跃interest_units决定，不随机初始化大量无语义向量。槽包含：固定锚点a、可学习中心u、正负样本摘要、固定领域/优先级/问题、短期状态、有效样本数与embedding版本。领域、明确排除和全局用途不是几个点击可改动的参数。

### 7.1 Q/K/V类比

- Q：某个用户兴趣槽（例如SSG中的群论构造）。
- K：新闻/论文的主题、方法、应用等**分面**向量，不是只有孤立“SSG”标签。
- V：分面对应的原文事实及可用于解读的证据定位。
- 匹配权重：由语义相似度、用户任务和确认约束计算，用于定位“这篇的哪个部分与我有关”。
- 反馈：调整后续槽的局部中心、分面偏好和置信度，不能把被喜欢的事实写成更真。

只保留整篇一个向量容易丢失“方法研究者看群论，材料研究者看能带解释”的差异。因此资料可保存主题、方法、应用、影响等少量分面；初期利用题名/摘要/已有标签及已获取片段，不在排名前为整库强制读全文或调用一次LLM。选出最终列表后才按相关分面重点读正文/写短解读。

### 7.2 算法选择

| 方法 | 可借鉴之处 | 当前选择 |
|---|---|---|
| Rocchio相关反馈 | 原始查询+正例靠近−负例远离，容易解释和撤回 | 首先实现锚定、多槽、带反馈强度的改造版 |
| 多原型/在线聚类 | 不将物理研究和AI求职平均为一个中心 | 每确认兴趣一个或少量槽，新增/拆分先建议后确认 |
| MIND / ComiRec | 多向量用户表示、匹配不同兴趣、相关性与多样性平衡 | 借鉴结构，不直接训练需要行为数据的完整工业网络 |
| 小特征在线逻辑回归 | 用显式标签校准“可能有用”，用可见曝光另估计打开倾向 | 有足够有效反馈后再引入，保留先验和冷启动回退 |
| LinUCB / contextual bandit | 用上下文与不确定性控制少量探索 | 接在安全门槛后，仅用于个人栏探索位置；不替代公共新闻价值 |
| 从头训练Transformer/双塔 | 可表达复杂兴趣演化 | 现在不采用：样本、工程、可解释性成本不匹配 |

推荐冻结编码器候选multilingual-e5-small，模型卡说明384维并有前缀规则；用于对称语义分面特征时统一采用其相应语义相似度前缀策略，不能混用不同模型、prefix或未归一版本。是否选它须以中英混合、SSG缩写消歧、群论/材料分面的本地对照测试决定，不保证通用榜单最好模型就适合此场景。下载及依赖安装需后续明确实施，不在本轮执行；既有聊天API可用不代表支持embedding接口。外部embedding服务会接触用户兴趣文本，必须另行确认数据发送范围。

### 7.3 可先模拟的锚定多槽Rocchio

对槽j，将该槽匹配的同领域内容分面编码为归一向量x。根据修改后最新反馈状态，重放一个有界时间窗：

```text
P_j = Σ(正反馈强度×时间权重×槽归属权重×x) / (κ + Σ正反馈权重)
N_j = Σ(负反馈强度×时间权重×槽归属权重×x) / (κ + Σ负反馈权重)
候选中心 u_j = normalize(a_j + βP_j − γN_j)
再将u_j投影到锚点a_j周围允许的角度/领域范围
```

κ是冷启动先验，避免一个弱点击被归一成与一个明确点赞同样强的正例。初始可试κ=5、β=0.6、γ=0.2、最大偏转20°；这些是模拟参数，不直接写入生产推荐。反馈只分配给相似度合格的少数槽/分面；没有匹配槽则保留临时样本、提出新兴趣建议，不强塞进最接近但实际上不相关的槽。低相似度情况下softmax总会分配权重，故softmax之前必须有“无匹配”门槛。

负反馈除中心更新外，保留少量局部负例，用于降低同一不相关应用的重复推荐；对与锚点完全同向的负例，单纯向量归一可能不产生方向变化，应修正局部偏好/去重而不是宣称已学会排斥。疑似原因不明的点踩小幅作用，必要时用对话澄清。明确“太难/来源有误”的解释要从主题负例训练集中撤回，转到阅读程度/核验通道。点击只改短期或弱正例，不创建新的永久大方向。

长期锚点固定，近期中心/权重可以衰减；例如短期状态7—14天、长期有效样本更慢衰减，具体半衰期靠实验。允许重置学习、撤回投票和禁用点击个性化。保存有界事件状态与checkpoint，替换/撤回后重算，不在一个已经漂移的向量上无限累积相反修补。每次更新限幅、账号隔离；模型升级重新编码已确认锚点及有效样本，不直接混算不同坐标系。

### 7.3a 本轮合成模拟（非真实语义模型）

项目Python 3.11在内存建立三维单位向量：相同初始锚点normalize(1,1,0)，群论分面normalize(0.96,0.26,0.1)，材料分面normalize(0.26,0.96,0.1)。分别输入30次有用和反方向30次点踩（点踩总权重9），使用上述κ/β/γ；点击对照为30次点击总权重3、无点踩。没有下载embedding、读取真实论文、访问账号或请求模型。

| 合成状态 | 对群论向量相似度 | 对材料向量相似度 | 偏转锚点 |
|---|---:|---:|---:|
| 相同冷启动 | 0.8630 | 0.8630 | 0° |
| 群论正反馈／材料负反馈 | 0.9569 | 0.7269 | 13.53° |
| 材料正反馈／群论负反馈 | 0.7269 | 0.9569 | 13.53° |
| 仅点击群论方向 | 0.9070 | 0.8150 | 5.44° |

这只证明在设定坐标/反馈下用户可分化、弱点击影响较小，且本例未触及20°上限；不证明真实编码器具备相同语义能力，不证明推荐准确率或最佳超参。相似度不是用户喜欢概率。

### 7.4 温度与探索

先用领域/排除/可信度/已知时间和相关邻域确定合格集，再用softmax或bandit选择小量探索条目。推荐temperature控制合格集内的分散，radius控制可以走多远，探索比例控制数量；不要给向量坐标随意加高斯噪声。默认探索可以从个人栏10%—20%试验，公共两栏不随机探索未核实大新闻。反馈多后可研究LinUCB的不确定性，而不是把多个启发式加分称为统计置信区间。

## 8. 召回和架构接入位置

个人候选：现有订阅/专业检索+已确认兴趣路由+后续向量邻域。公共候选：另设与个人兴趣无关的通用新闻/官方通告/重要领域RSS；必须有真实采集预算与覆盖状态，不能只在原个人12源结果里挑“大事件”。热榜候选：公共报道聚合及实际接入的榜单/互动观测。

共享公共候选只能来自允许共享元数据的公开来源；私人源内容、私人查询、个人向量、点赞/点击不能被拷入其他用户公共池。现在所有Feed池按账号隔离，这个约束继续保留；可先在每账号范围合并内置公共来源，而不是未经授权引入全用户共享新闻库。

建议保持现有边界，增量模块如下（均为拟议名称）：

| 层 | 计划职责 |
|---|---|
| sources/ | 公开覆盖、平台观测字段、发布/观测时间，不处理私人画像 |
| event signals | 保守同事件聚合、独立来源数、C/I/H证据和版本；复用news_repository事件候选但不能把同主体当同事件 |
| interaction_repository | 真实可见曝光、用户原文打开、互斥投票及撤回；幂等/去重、位置/栏目/版本 |
| embedding provider | 冻结编码器及版本缓存，便于换本地/外部实现，不绑定agent_core |
| profile learner | 锚定多槽Rocchio、短长状态、局部负例、确认边界和重放 |
| recommendation.py | R及三栏可解释加权，安全门槛与少量受控探索 |
| news_pipeline.py | 事件/评分缓存、三栏去重选取、只对最终总预算N条正文解读 |
| desktop/news_view.py | 卡片点赞/点踩/打开原文、三栏入口、简洁分数解释 |

现有displayed是卡片被渲染，不是真正进入视口；不能拿它直接算CTR。计划用例如卡片至少50%可见并持续1秒作为可见机会的初始定义，记录section、position、时间、policy_version。这个定义只描述展示，不保证用户读过。按真实有效曝光计分母、同会话去重；曝光延迟和误触/打开失败单独处理。

记录紧凑事实，不保存每篇评分推理：事件/文章ID、用户、观测类型、来源、时间、投票状态、位置、栏目、策略/画像/编码器版本、已选条目的条件概率。点击训练默认本机、可关闭和清除，不自动上传全部历史给模型。向量仍可能泄露兴趣，不应因“是向量”就称为匿名。

## 9. 实施优先级与验收

P0：先统一卡片两按钮、原文打开计数、可见曝光和撤回；所有新闻可反馈。先只记录，不偷偷训练；旧星级保留。测试互斥/幂等、同事件跨报告、关闭学习、跨账号拒绝、网络打开失败不记成已阅读。

P1：接入冻结embedding、按确认兴趣建槽、离线重放多槽Rocchio。以两个读者对同一SSG资料的不同偏好测试；同时验证同一初始宽泛画像在不同反馈后分化。检查弱点击不压过点赞、单次点踩不删领域、无反馈不更新、反复打开不刷权重、负例局部性、撤回可恢复、编码器升级一致性。

P2：公共覆盖与保守事件聚合、C/I/H有依据特征、三栏权重和总N预算。用“重大但不热/很热但不重要/独立多源与转载/新可靠源无历史/未知日期/私密来源”对照。置信不足热榜不伪装全网热榜，重要性不由用户兴趣先过滤。

P3：数据充分后校准R/U/O与栏目权重，再比较softmax、LinUCB、小特征逻辑回归。保留固定基线，按时间切分，防止同事件泄漏。离线合成仅证明机制；真实指标以有用率、明确负反馈率、覆盖/重复率、来源质量和画像稳定性为主，原文打开率为辅，不以CTR上升单独验收。置信区间和未反馈偏差需要说明。

当前只保存逐位置条件概率和候选数，不足以无偏评估任意整列表策略；不要把它直接套成整列表IPS。将来要做反事实评测，需明确目标策略支持、候选集合/采样机制、曝光偏差及有界权重，不能伪造没有观察到的奖励。
