# 分层多兴趣语义画像

## 结构与使用

大类由用户命名并控制，只作为分组/路由边界，不生成大类向量。每个大类包含一个或多个细分兴趣向量；同类且相近的细分兴趣共享一个向量。类别、种子主题、初始锚点和反馈后的向量分别存储，不将类别名称送入语义编码器。

```text
用户确认的凝聚态理论（分类名称，不编码）
  ├─ 群论中的投影表示、群的射影表示理论 → 共享兴趣向量
  └─ 其他不够相近的方法主题 → 独立兴趣向量
用户确认的AI算法（分类名称，不编码）
  └─ 大语言模型强化学习与推理 → 独立兴趣向量
```

入口：“兴趣与领域→兴趣分类与语义画像”。点击“编辑分类与兴趣”，给细分兴趣填写大类，保存全部；旧的简单主题可先“导入关注主题”到编辑草稿，确认保存才生效。最多12个细分单元、30个简单主题；旧主题未分组时各自保留“未分类·主题”，不擅自归并为一个泛化向量。聊天可提出含category的档案建议，仍由用户确认。过期单元不使用，也不因同名简单主题而复活。

“准备本地语义模型”显式下载约220MB公开文件，不需要模型Key；准备完可“按当前反馈重建画像”。树展示大类、共享主题、关联反馈数和偏转角度。赞踩记录即时保存，向量在下次生成/重新整理或点击重建时刷新，不自动改写历史简报。画像开关按账号保存，默认启用但缺模型时明确回退，不偷偷下载。“指标权重”的反馈学习开关关闭时只用初始向量，不使用历史赞踩/打开。

## 编码和新闻匹配：不经过解码

TextEncoder协议只规定encode、dimension和version，业务不依赖具体SDK。当前为FastEmbed 0.9系列、CPU ONNX量化的paraphrase-multilingual-MiniLM-L12-v2，384维、多语言。模型来自[公开模型仓库](https://huggingface.co/Qdrant/paraphrase-multilingual-MiniLM-L12-v2-onnx-Q)，固定revision为faf4aa4225822f3bc6376869cb1164e8e3feedd0，只下载声明的7个文件；token=False，不借用其他客户端认证。

模型文件在data/embedding_models/<revision>；日常编码local_files_only，不上传兴趣或新闻到embedding服务。模型由进程缓存，2个CPU线程、每批32段，线程锁避免并发使用同一实例。依赖通过项目requirements安装；轻量安装可选semantic extra。

所有向量先单位化。同一固定编码器E把兴趣描述、新闻文字和标签转到同一坐标系，直接计算cos(p,x)=p·x；不需要把p转换成词表概率或还原成文字。未知/零/非有限或维数错误的向量拒绝。相似度是几何分数，不是点击概率。

- 兴趣种子：主题+方法+具体问题；不编码大类名称、用途或知识程度。后两项仍交原AI评分/解读处理。长描述按200字符分片后取归一化均值。
- 新闻主体：标题前200字符、摘要前600字符（每200字符一片），标题权重2，各摘要片权重1，取归一化加权均值b。
- 提及标签：最多4个主题/方法标签，各自编码，平均为t；贡献标签不参与。新闻向量x=unit(0.85b+0.15t)，没有标签只用b。没有词表命中仍可匹配新闻本身。
- 该模型每段上限128 tokens，字符分片仍可能被截断；这里是标题摘要级推荐特征，不冒充全文理解。正文阅读依然只在最终入选后进行。

## 类内合并与固定路由

在同一个明确大类里执行确定性complete-link聚类：两个簇中所有跨簇种子对的余弦都至少0.72才合并，避免A接近B、B接近C就把远离的A和C连成一团。跨大类永不合并。簇内种子按用户priority加权得到单位初始锚点a。聚类依据确认种子，不随每次反馈反复拆合；用户编辑兴趣后重新计算。

新闻匹配先经过已有来源domain的粗约束（相交或general），再比较各细分锚点。保留锚点余弦至少0.30的候选；大类得分是该类最高子锚点分，不是大类embedding。反馈仅分配给最佳大类；前两类差小于0.04时跳过，避免把跨学科或含糊反馈写进错误方向。该门槛不是严格学科分类器，来源domain本身也可能很宽。

同类里保留距最佳锚点不超过0.12的槽，attention=softmax(cos(a,x)/0.12)，得到反馈责任比例。temperature只控制类内分配，不跨大类探索、不改变聊天模型温度。排名可以选择相似度最高的大类，但模糊新闻反馈不学习。向量更新后的偏好不用于反过来扩大归类边界。

## 可撤回、带锚点的反馈学习

按账号+规范URL去重，同篇最多一条有效观测：显式赞/踩优先，仅打开是弱正例。点赞/点踩基础质量权重1，打开0.1，时间权重为2^(-天数/90)；未点击/未评价不是负例。重复打开只累计显示次数，不增加学习样本、不刷新首次打开的学习时间；老记录不能追溯恢复变更前的首次时间。显式票更新用新反馈时间。

令w包含上述权重和attention，对每个槽分别累计正负方向：

```text
W+ = Σ正例 w              W- = Σ负例 w
P = Σ正例(w × 新闻向量) / (3 + W+)
N = Σ负例(w × 新闻向量) / (3 + W-)
p = unit(a + 0.75P - 0.35N)
p = 限制在相对初始锚点a的25°圆锥内
bias = 0.08W+/(3+W+) - 0.15W-/(3+W-)
```

先验3使少量反馈不会迅速淹没初始意图，负例方向系数较小；点踩可能是质量问题，不应一次抹掉整个方向。bias是有界的细分兴趣强度：当负例恰好与锚点同方向时，仅归一化减向量不会改变角度，bias仍能降低这个槽的亲和分。它不是高层领域权重。

重建时从原锚点和当前有效反馈重算，不把同一记录一轮轮重复梯度训练。最多读取各5000条赞踩/打开，合并后采用最近1000个规范URL观测；90天半衰期逐渐减弱旧偏好。撤回/改票后重建即可移除/替换贡献，全部撤回恢复锚点；清除反馈也删除本账号派生画像。来源已不可见、新闻缺失、归类不可靠的反馈跳过，不借其他账号的新闻补全。

这是带约束的Rocchio式在线偏好统计，不反向传播、不训练编码器或Wq/Wk/Wv。可类比Q=兴趣锚点、K=新闻向量、V=新闻向量，attention负责把观测分配给槽；赞踩另决定更新符号与强度。并非把attention直接替换成点击率，也不是Transformer语言生成。

## 接入现有排序与解释

每条已评分候选，在所选类的合格槽内取max(cos(p,x)+bias)，不平均不相关兴趣。语义分S=clip((相似度-0.2)/0.8×100,0,100)。这是待校准的线性映射，不是概率。原AI兴趣分A保留，关联性R=clip(A+Δ,0,100)，其中Δ=clip(0.25×(S-A)+同篇显式赞踩±4,-20,20)。没有可靠匹配则Δ=0；直接票是既有同篇偏好修正，非额外原文点击加分。

向量路径替换旧有限标签残差，不双重叠加；本地模型缺失、关闭或失败时保留原有限标签校正，报告记录fallback状态。C/I/H不受兴趣反馈训练，三栏权重、共同解读数量和原AI评分缓存仍沿用。语义路径active时不再叠加旧概念bandit随机抽样；未来真正的向量邻域探索需要另行评估。

处理顺序：采集/存库→全候选AI评分→本地向量编码及画像重建→合成关联性和三栏→只给最终N条补读/解读。首次编码有CPU成本，之后按账号/模型/文本摘要复用缓存。没有额外聊天API请求。入选卡片只显示确认主题、类别、匹配提示；完整向量不送LLM，不在报告复制全库向量或逐条推理。

## 持久化、模块和失败处理

- semantic_profile.py：纯单位向量、种子、合并、路由、反馈重建、匹配。
- model/embeddings.py：固定模型下载与离线编码；agent_core/protocols.py定义TextEncoder。
- research/semantic_personalization.py：分片特征、缓存、历史观测重建、排序融合；session可注入其他编码器以便测试和更换。
- database/semantic_repository.py：semantic_settings账号开关、semantic_text_vectors文本摘要/向量、semantic_documents新闻/标签特征、semantic_profiles锚点与派生状态。每次操作校验账号归属。
- desktop/semantic_profile.py、interest_editor.py：后台准备/重建、分类编辑、状态树；news_view.py展示匹配和降级。

编码模型revision与特征版本共同隔离缓存，不混用坐标系。用户分类或反馈变更使画像待重建。取消在批次与提交前检查，已完成编码缓存可保留，但不提交半成品画像；阻塞下载不保证即时取消。缺依赖、模型错误、无效向量明确回退，既有新闻和原AI分不丢失。账号隔离不等于SQLite加密：能读取数据库的人可读取向量与档案。向量不是匿名数据，不上传、不共享、不提交Git。

## 验证和已知限制

多轮对照实验由research/feedback_experiment.py及feedback_experiment_report.py实现，使用已准备的真实编码器、120条虚构材料、64条反馈材料、40条未见评估材料、20个固定种子，比较不学习、正常赞踩、20%误点、仅打开、偏好反转。保留完整K/V特征与种子0的向量轨迹，输出P@10、nDCG@10、模拟基分融合效果、偏转角、主题熵及撤回/衰减检查；只运行在临时账号数据库，不读取生产画像。详见[实验方法与实测结果](feedback-evolution-experiment.md)。这类模板控制实验不能证明真实用户准确率；不训练QKV，也没有主动探索。

项目Python 3.11虚拟环境：

```powershell
.venv\Scripts\python.exe -m newspaper_agent.model.embeddings --download
.venv\Scripts\python.exe -X utf8 -m newspaper_agent.research.semantic_evaluation
.venv\Scripts\python.exe -m compileall -q src tests
.venv\Scripts\python.exe -m pytest -q
```

第一条显式联网准备模型；第二条使用真实本地384维模型、虚构控制材料和临时数据库，不读生产账号、不调用LLM。evals/semantic_profile_cases.json固定同类近义兴趣、数学/材料/AI/无关新闻。一次控制实验：两个投影表示主题合并，AI主题独立；数学材料匹配余弦0.632，点赞后0.727，点踩后0.575；AI槽不动，撤回恢复；烹饪案例未通过匹配门槛。跨语言“群论与投影表示”的中英文余弦约0.8335。它们证明当前实现行为，不证明真实推荐准确率。

tests/unit/test_semantic_profile.py覆盖分类保留、过期/旧主题、完整链接、跨类隔离、负例共线、角度、衰减、弱点击、撤回、缓存版本、账号隔离、降级与Qt；news_pipeline测试验证全候选编码先于最终10条解读，LLM调用量不增加。当前完整506项通过。

仍未实现：训练式QKV、词表概率解码、专业领域embedding微调、全网向量召回、ANN索引、真人A/B与无偏CTR学习。通用小模型对专门数学术语可能区分不足；0.72/0.30/25°和融合系数是工程初值，不是普遍最优参数。少量或含糊反馈宁可暂不学习；明确大方向、用途和程度仍由用户声明。

研究依据：[Sentence Transformers相似度](https://sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html)、[MIND多兴趣表示](https://arxiv.org/abs/1904.08030)、[Rocchio反馈](https://nlp.stanford.edu/IR-book/html/htmledition/the-rocchio-algorithm-for-relevance-feedback-1.html)。组合与阈值是本项目针对少反馈本机应用的工程选择，并非复现MIND训练或已验证的最优模型。
