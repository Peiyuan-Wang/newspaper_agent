# 兴趣确认与表达适配策略

## 职责与边界

SQLite保存长期档案、候选确认、版本和撤销。新闻由AI评估兴趣分，再以本地分层语义画像校正关联性，合成三栏并解读共同N条（默认10）；研究对话按任务选择取证。人工星级不训练推荐；主卡片赞踩/弱原文打开有界更新细分兴趣向量，不训练编码器或语言模型。

自进化指受用户确认约束的本机档案、来源与提示内容更新，不是微调权重。理解收益与推荐准确率没有经过真实用户benchmark验收。

## 如何开始

先启用模型，进入“兴趣与领域”，点击“让AI访谈我的兴趣与表达偏好”，再发送预填的问题。也可以直接聊天：

> 我研究AI Agent，目的是学习架构并判断哪些工具值得尝试。我关心工具调用、记忆和真实落地，基础模型跑分暂时不是重点。我是入门者，希望先讲具体变化，再用表格对比。请先询问并确认你的理解，再提出档案建议。

AI每轮最多询问3个关键问题；先弄清用途、细分兴趣、正反例和知识水平。提出候选后，到“兴趣与领域”查看原话、理由和修改前后值，确认或拒绝。只有一项待确认建议时，也可以在聊天明确说“确认档案建议”或“拒绝档案建议”；多项需界面选定或在原话中指定建议ID。“是的”或讨论事实的“确认AI能否…”不会被程序当作档案确认。

人工填写档案并保存是直接生效；原有record_feedback仍可保存用户原话明确支持的关键词/详略变化。AI自行归纳的偏好先进入候选。确认后的变更在“反馈与改进”可撤销，旧版本不得覆盖新偏好。

涉及兴趣、档案、表达、风格、术语等任务保留完整工具循环，避免快速模式在取得文章后跳过候选提出。额外自动发送历史反馈摘要到模型的扩展被自动审批拦截，尚未实现；它需要用户明确批准反馈内容范围和外部模型服务目的地。

## 策略一：确定兴趣

1. **任务用途先于主题标签**：同样关注Agent，学习架构与选择商业产品需要不同信息。
2. **细化维度**：interest_units分别保存主题、领域、具体问题、用途、方法、领域程度、优先级和可选截止日期，最多12项。“兴趣与领域→细分兴趣与阶段目标”可视化编辑并明确保存；聊天整理仍须确认。到期只暂停使用、不删除历史。不把一次检索视为永久兴趣。详细契约见[画像与覆盖](personalized-news-routing.md)。
3. **用反例纠偏**：遗漏一篇文章时区分主题理解、来源覆盖、筛选排除；另外区分重复/无新信息、太浅、太难、来源质量和今天暂时不想看。这五类仅记录原因，不自动改长期兴趣/排除/风格，需另提待确认建议，不直接把整个领域加权或屏蔽。
4. **候选与确认分开**：`propose_profile`保存变化、原话、理由和当前版本；不修改生效档案。用户确认通过`resolve_proposal`在同一事务中写档案和事件；拒绝保留状态但不生效。
5. **每次任务复用**：领域辅助来源路由；新闻库由AI基于完整已确认兴趣、用途、领域、知识水平和排除偏好打0–100兴趣分，不用词法重合代替兴趣分。研究聊天的明确问题取证仍可用关键词门槛。来源演化走个人发现、验证、启用和共享审核。

`research_profiles`保存有效档案，`research_profile_proposals`保存候选与确认状态，`research_events`保存版本变化和撤销轨迹。按账号隔离，管理员也不获得其他人的个人建议。待确认最多20项；档案被其他操作更新后，旧建议需要重新提出。

AI兴趣分表达模型对明确档案与新闻内容匹配的估计，不是置信概率或已验证准确率；按内容、档案和模型版本缓存。[分层语义画像](semantic-interest-profile.md)通过可选category保存用户命名的大类，类内合并近义细分兴趣，并以赞踩/弱点击更新连续向量，直接与新闻编码比较，不还原token。大类不编码、不由反馈改名；原始分保留，语义仅有界校正关联性。画像和反馈留本机，原始向量不发送给LLM。可选[上下文探索](contextual-exploration.md)仅在语义未active且无公共配额时兼容使用；人工星级独立，长期明确兴趣改变仍须确认。

## 策略二：优化语言与组织

- `purpose`：阅读用途，最多300字符。
- `knowledge_level`：beginner/intermediate/expert，全局默认术语解释程度。
- `domain_reading_rules`：最多30条×120字符的分领域阅读约定，在界面逐行编辑或由聊天提出候选，经确认生效、可撤销。例如“凝聚态：expert，优先群论构造”“AI：beginner，解释术语”。解读按当前文章语义适用，优先于全局程度，不将一个领域的入门程度推广到其他领域。
- `output_format`：cards/table/outline，决定卡片、比较表格或编号提纲。
- `expression_rules`：最多30条，每条120字符，例如“先讲变化与影响”“机制按输入、处理、输出解释”。
- `glossary`：最多30条，每条120字符，保存用户确认的术语解释约定；这是阅读约定，不是领域事实已被核验的证明。
- 原有`style`和`language`继续控制详略和语言。

用户提供喜爱的文章或指出“太抽象、太长、术语不懂”时，模型归纳可执行规则，提出候选让用户确认。下一次综合发送用途、默认知识水平、结构、最多30条分领域规则/兴趣及最多12条表达规则/术语；不把密钥或任意个人字段混入请求。新闻前十条使用专门短解读契约，选一个兴趣视角、最多2条主张，中文正文最多180字符，超长反馈修订，不直接截断。研究综合保留原长版。详见[读者专属短解读](personalized-news-brief.md)。

表格由程序确定性渲染：重点、适用条件、尚不能确认、依据，所有来源仍可点击。无模型时表格只显示题名、短摘录、日期和栏目，不假装有模型解读。原始证据保留，关键条件不因表格或短版丢弃。提纲和卡片仍采用同一份证据知识对象。

术语可以通过你提供的约定和AI建议持续积累。尚未实现自动从领域文献抽取、核对并更新带出处的术语库，也未自动生成因果图/知识图谱。流程图需要可靠关系证据，不能为视觉完整编造因果。表达适配实际效果仍需真实模型和读者评价验证。

## 验证与安全

Python 3.11项目虚拟环境执行compileall和pytest。离线测试覆盖确认前不生效、跨账号拒绝、事务批准与撤销、旧版本冲突、明确聊天确认、多候选歧义、默认值不跨用户共享、规则进入模型白名单、表格连续行与条件保留、桌面访谈入口。全部测试不请求真实模型，不在生产数据库建立测试账号。

历史账号读取时补齐新增默认字段，不删旧数据；之后按正常版本更新持久化。个人偏好只进入当前用户的模型请求，不随共享来源发布。模型仍可能误解用户或提出错误建议，需要用户检查候选；候选审批不能替代事实核查。

验收：完整测试270项通过，compileall通过；已确认Qt实际生成4列表格，而不是把Markdown竖线作为普通文字显示。真实模型请求为0；表达与理解收益未做真人实验。
