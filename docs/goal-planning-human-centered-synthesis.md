# 目标规划：面向人类理解的信息筛选与知识综合

日期：2026-10-12。状态：架构审计与候选路线，尚未实现；本次只归档原文和更新规划。

后续进展（2026-10-13）：用户授权完成第一版后，真实来源、筛选、个人反馈、证据卡片、解释策略与对照入口已按轻量路线实现，详见 [第一版手册](research-v1.md)。下文保留2026-10-12审计时点，不能将历史“尚未实现”视为当前状态；原文仍是非排他性参考。

参考：[原始方法论文档](human_centered_knowledge_synthesis_methodology.md)。原文来自用户 Downloads，保留其内容（换行格式可规范化）。其中“给 Codex 的约定”、示例 Skill 和任务描述仅是参考材料，不是新增项目规则、自动执行指令或必须全部实现的规范。原文引用论文、博客的题名、年份、有效性尚未在本轮逐一核验，落地依赖具体研究结论前再查原始资料。

## 1. 适合当前项目的目标

现有目标是轻量、模型可替换、按领域收集资料，并逐步形成用户自己的信息来源助理。本参考补充了输出侧目标：不是尽量少写，而是让读者在合理时间内取得可理解、可核验、可复用的知识。

保留现有来源架构，不把信息源自动扩充与知识综合混成一个功能。前者解决“去哪找”，后者解决“哪些值得看、如何组织、怎样解释”。本阶段不增加账号、依赖、联网请求、数据库表、Prompt 或 CLI 行为。

## 2. 当前能力审计（以源码而非目录名称为准）

| 能力 | 已有实现及入口 | 与方法论的重叠与实际缺口 |
|---|---|---|
| 可替换模型 | `model/client.py`、factory；Chat/Responses 共用客户端 | 可以复用；协议兼容不代表支持结构化输出强约束或内置搜索 |
| 工具闭环 | `agent_core/loop.py`、ToolRegistry；默认四轮/八次工具执行，失败不提交本轮对话 | 符合单 Agent 按需工具路线；还没有研究综合阶段与输出核查 |
| 来源筛选 | `sources/catalog.py` 按领域、类型、语言、地域选择启用来源，跨领域覆盖、有限偏好排序 | **来源路由已实现，不等于检索结果质量筛选**；缺少去重、正文相关性、版本与独立来源判断 |
| 检索与读取 | `sources/service.py` 仅 FixtureAdapter；两个 information 工具可被模型调用 | 当前只有固定虚构样例，不能证明真实检索质量；Tavily 请求草稿未接入统一链路 |
| 证据表示 | EvidenceRecord 有来源 ID、URL、片段、获取/发布时间、类型、payload | 是文档/结果级追溯基础，不是主张级核验；缺少正文快照、版本、定位、证据支持关系 |
| 个人来源反馈 | SQLite SourceRepository 保存候选、useful/irrelevant/fact_error、撤销；sources CLI 使用偏好 | 候选仍禁用；fact_error 只记录；主程序 --information 未接个人偏好；没有理解/表达反馈 |
| 短期/长期记忆 | ShortTermMemory 窗口和 SQLite 键值记忆可单独使用、长期记忆有往返测试 | 没有接入主对话链路；不是跨文献知识库。不能直接把回答当作已核验记忆 |
| Prompt 与输出 | app 在 --information 下加载 information.md；最终 Message.content 直接打印 | 已提醒虚构来源、未知日期、外部内容不可信，但仅为提示；system/planner 文件未由 app 加载，没有真正解释规划/分层渲染 |
| MCP、UI、观测 | MCPClient 是占位连接/空工具列表；CLI 是当前界面；logging 是基础配置 | 不具备正式 Skill 加载、网页阅读 UI、理解评测或成本追踪；不宜先做复杂交互层 |
| 测试 | 工具边界、路由、反馈与双协议模拟 HTTP 等回归测试 | 验证工程链路，不验证事实准确、引用支持、人类理解或真实来源质量 |

特别风险：当前 fixture 的 evidence_id 按来源固定，不同查询可能覆盖缓存。离线教学可用，真实来源应采用稳定文档 ID + 版本/快照标识，避免“同一 ID 指向变化资料”。读取时间不是发布时间；搜索摘要不是已读取全文；虚构样例即使字段标为 fulltext 也不是事实依据。

## 3. 方法的适用性判断

| 方法 | 建议 | 原因 |
|---|---|---|
| 任务相关性、去重、原始来源与多样性 | 高优先级采用 | 直接改善输入资料；复用 SourceService 的结果边界 |
| 原子主张 + 原文锚点 + 条件 | 小规模采用，先关键结论 | 解决链接存在却不支持结论的问题；不需立即拆解每一句 |
| 结论前置、术语就地解释、按需展开 | 早期低成本实验 | 符合用户理解需求；以新增可选 Prompt 和 Markdown 渲染试验 |
| 条件/争议保留与最终回查 | 必须作为质量约束 | 简洁不能以删掉反例、适用范围或不确定性为代价 |
| 知识卡片、轻量概念索引 | 待复用需求出现后采用 | 适合持续调研；先 JSON/SQLite，不引入图数据库 |
| LLM 自评与冲突识别 | 仅辅助待查 | 不等于事实核验；不同日期、对象、单位和定义会造成假冲突 |
| GraphRAG、RAPTOR、大图谱 | 暂缓，不是永远排除 | 尚无真实资料规模与跨库检索失败证据；索引/维护成本过早 |
| 八角色多 Agent / 多轮反复压缩 | 当前不适合默认启用 | 延迟、费用、上下文和错误传播增大；职责可用函数表达 |
| 形式验证、训练/RL/偏好模型 | 当前不适合 | 新闻与一般研究不是证明验证任务，也没有足够评测/训练数据 |
| 多层网页 UI | 暂缓 | 当前 CLI；先支持一层正文加“可展开主题”，不一次输出三份全文 |

以上为针对项目阶段的工程判断，不是已经验证的收益结论。

## 4. 三种集成选项

**A：仅解释策略（成本最低）。** 在 app 组装时按显式开关加载新 Prompt，规定结论、关键依据、必要限制和可展开主题。通常不需要额外模型调用；不可声称能核验资料，也不能弥补真实检索缺口。适合先拿固定资料做 baseline 对比。

**B：轻量知识综合模块（推荐逐步走到这里）。** 在来源工具返回边界加入确定性筛选；关键结论由模型提取为小型结构化知识对象，再做引用/锚点检查和 Markdown 渲染。复用模型客户端与 SQLite 持久化边界，新增独立 synthesis 模块，app 负责组装。先会话内处理，不默认存知识库。

**C：完整研究 Harness。** 多阶段规划、发现、全文解析、跨文献关系索引、知识库与交互 UI。作为远期候选，只有 B 的测评和真实任务证明有必要才设计；本轮不批准或实施。

推荐顺序：A 的低成本解释实验可与真实来源接入并行准备；先完成真实来源和确定性筛选，再试 B 的关键结论证据卡片；不急于 C。

## 5. 最小 MVP 的具体设计（候选，需后续确认）

### 5.1 信息筛选：先透明规则，后语义排序

候选位置：`sources/filtering.py`，输入 SearchRequest + EvidenceRecord 列表，输出保留记录及筛选原因，SourceService 在返回工具结果前调用。保留原始检索记录供审计，而不是覆盖来源结果。

- 精确重复先用规范化 DOI/arXiv ID；没有可靠 ID 时使用经过审慎规范化的 URL。不要简单删除所有查询参数，有些代表实际文档或版本。
- 同一文章转载应分组，不算多个独立来源；相似标题只提示可能重复，不默认合并。观点相反不构成重复。
- 根据题目、类型、时间约束做相关性检查。发布时间未知则标未知，不假设最新；来源权威性与是否支持本题分别判断。
- 选择有限、互补的资料；保留重要反例和冲突。记录排除原因，可查看、回滚。
- 不一开始采用未经校准的加权总分。先规则可解释，再考虑词法/语义重排；多语种相关性不足且数据规模扩大时再评估向量模型或重排服务。

### 5.2 知识组织：证据卡片，不先建知识图谱

候选位置：`synthesis/contracts.py`、`claims.py`、`validation.py`。用 Python 3.11 dataclass + 标准库 JSON 起步，无新数据库/模型 SDK 依赖。

建议 Claim 字段：id、statement、conditions、evidence_refs、uncertainty、status。EvidenceRef 至少包括 evidence_id、document_version/snapshot_id、locator、quote；定位可以是段落、页码或章节，不能由模型凭空生成。没有正文时只能引用摘要/元数据，不能冒称全文已支持。

首先只保留 `unverified` / `source_supported` / `disputed` 这类可解释状态，并记录谁以什么方式检查。模型提议的主张默认未核查。代码确认引用存在、引文出现于快照，仅证明锚点有效；**是否真正支持主张仍需语义判断或人工核对**。未经核对不能因为引用合法就自动升级 source_supported；跨源核查也需记录独立来源与核查方式。暂不提供 formally_verified 标签。

关系先限于主题分组和明确冲突，标注“来源陈述”或“系统推断”。新闻事件按时间/实体分组，学术资料按问题/方法/结果/局限组织，不强制所有领域使用同一概念图。

### 5.3 简洁与理解效率：一个输出，不是三份重复内容

候选位置：`prompts/explanation.md`、`synthesis/rendering.py`。读者配置只收集主动提供的背景、用途和篇幅偏好，不推断敏感画像。默认：直接结论、少量互补要点、关键限制和证据；短/标准/专业选择一层，专业版保留准确术语。

“快速版”是阅读目标，不保证每个人 30 秒读完；不机械要求少于固定 token。复杂内容按需增加定义、一个例子和适用边界。区分事实、解释、推断、建议；简短版也不能遗漏改变结论的条件。CLI 先提示可追问主题，网页折叠/图表等以后再决定。

### 5.4 集成、兼容和失败行为

- 保持 AgentLoop 只依赖协议。由 app 组装可选 SynthesisService，不让核心循环直接 import sources、数据库或具体模型服务。
- 第一阶段用 Prompt，不修改 Message/model_data 的协议回放。第二阶段通过独立 schema 校验结构化知识对象，不要求所有中转站支持严格 JSON Schema API；用现有客户端提取 JSON 后本地验证，失败受控降级，而非无限重试。
- 后处理不能只拿最终回答：必须同时提供本次使用的原始证据，否则只能润色不能核查。可规划 SourceService 的只读证据快照接口，不解析/污染 model_data。
- 如后处理发生在 AgentLoop 已提交历史之后，不能仅改终端输出却让下一轮看到旧答案。优先先在原生成路径做 Prompt 实验；以后 B 阶段单独明确“草稿/展示答案/会话历史”的一致性提交或显式修订机制，再上线多轮模式，不偷偷回写旧历史。
- 拟议开关如 `--explanation off|brief|standard|expert` 目前不存在，默认 off、保持现有行为；测试禁用时零额外模型调用。提取/核查初期额外调用总预算建议最多两次，计入独立总请求与墙钟预算，不误认为受原四轮限制自动保护。
- 校验失败：不得显示“已核验”；可以返回标记为未核查的原始回答或明确资料不足。可选编辑失败不损坏原始证据，不自动持久化未经确认的事实。
- 外部正文仍是不可信数据；声明/提示词不能替代授权、安全访问与输出校验。持久化仅存授权资料，不存密钥、模型内部回放或未经同意的用户背景。

## 6. 优先级与依赖

| 优先级 | 阶段 | 具体交付 | 验收与推进条件 |
|---|---|---|---|
| P0 | 本轮归档/审计 | 原文、适配规划、README/进度索引 | 无代码行为变化；已完成文档工作 |
| P1-A | 真实资料基础 | 一个实际来源适配、证据 ID/日期/内容级别规范、安全与限流 | 真链接可核对；虚构资料不得混入事实依据；需另行授权实施 |
| P1-B | 筛选与基线 | 去重/来源分组/原因 + 10–15 个固定题目、固定资料包 | 无误删关键反例；可回放；先人工标注期望 |
| P1-C | 轻量解释 A/B | 可选 Prompt、单层读者偏好、人工阅读反馈 | 限定条件/事实不退化、开关可关闭；固定资料包即可试验 |
| P2 | 关键结论卡片 | Claim/EvidenceRef、小型验证器、渲染、会话一致性 | 引用有效且人工支持性抽检通过；再考虑持久化 |
| P3 | 可复用知识 | 已核对卡片、SQLite repository、主题/概念索引、表达反馈 | 重复调研需求明确；更正能传播到旧卡片并保留版本 |
| 暂缓 | 高复杂度候选 | 多 Agent、GraphRAG、图数据库、训练、网页知识图 UI | 有实测瓶颈和收益依据再批准 |

真实来源接入仍是原计划下一步，方法论不取代它。固定资料包上的解释实验无需等所有联网能力完成，但不能据此宣称真实研究质量已提高。

## 7. 测试与效果评估

工程回归：沿用项目 `.venv` Python 3.11、compileall、pytest，不进行真实付费调用。后续新增单元测试覆盖精确/近似重复、版本差异、未知日期、相反证据保留、越界锚点、伪引文、虚构隔离、JSON 无效和长度限制。集成测试覆盖两个协议、预算、关闭零额外调用、失败降级、下一轮看到的答案与展示一致。

小规模评测建议 10–15 题，每题固定材料、模型配置和目标读者；包含简单问答、新闻对比、学术概念解释、多来源冲突与资料不足。先 baseline 对比 Prompt-only，必要时再对比结构化方案，不一次引入全部变量。

分别报告：关键主张证据支持率、必要条件保留、关键反例覆盖、阅读时间、读后复述/理解题正确率、一个新情境应用题、感知负担、输出长度、模型调用数、token（有返回用量时）、延迟。价格按实际服务配置估算且标明估算，不将长度当真实 token 或把模型自评分当人类理解结果。

采用匿名化版本、随机阅读顺序，人工核对关键主张。小样本只报告描述性结果，不承诺显著提升。若严重事实/引用错误增加、关键限制丢失或成本不可接受，即停止/回滚；是否改善理解以真实读者结果为准。用户觉得“喜欢”不等于来源真实，来源偏好反馈与正确性、理解反馈必须分开保存。
