# 用户指定简报数量

## 使用

今日简报搜索栏有“最多10条”按钮。点击后直接输入1—100整数，按钮更新为所选数量，按本机账号记住，不改config。默认10条；可选1、25、100等，不限于预设档。超过10条在更新/AI重新整理之前确认费用，默认选择取消。这个上限是当前资源保护，不是检索库只有100条。

它控制**本次最多展示并解读多少篇**，不控制整库评分。仍为所有本次来源/时间范围内候选分批评分，再取最相关N条；候选不足N就显示实际数量，不凑新闻、不放宽时间，不重新评分仅因为输出数变了。开启兴趣拓展时N中保留floor(N×epsilon)个探索名额，原始兴趣分不变、清楚标明不是纯分数前N。

已有历史报告不会自动变长。用新的数量“更新简报”生成新报告，或点“AI重新整理”从该报告保存的全部library_ids中重新取前N并另存；不重新搜索、不覆盖旧报告。新报告保存requested_limit，普通业务API重新整理默认继承原数量；旧报告没有该字段按10兼容。

## 接口和预算

`news_options.py`集中验证1—100严格整数，拒绝bool/浮点/字符串/越界。`DesktopRepository.desktop_news_preferences`存账号的max_news；Qt按钮通过ResearchSession.search/resynthesize传给news_pipeline.generate_news及recommendation.select_news的max_news参数。

CLI仍默认10，Python业务API可传max_news。候选最多2400，评分按实际上下文/输出预算每批最多40条、兼容客户端最多两路；不因N增加抓取来源数。实际待评分批数B时最多`B+max(20,2B)`次评分，每条初次后最多补评两轮；最终K=min(N,M)另预留11K次阅读/写作。缓存全部命中无评分调用，HTTP重试另计。重新整理默认复用有效解读，不强制重写；仅改表达不重新处理长文已读分段。100篇长论文仍可能昂贵，不提高单请求额度或偷偷换模型，见[效率与缓存](efficient-news-scoring.md)。

## 大报告保存

数量增加不能靠抬高100万字符报告上限解决。每篇完整校验证据、引用、正文/断点和解读仍在独立news_interpretations等记录中。报告payload超过650000字符时，仅将evidence展示快照替换为原始标题/摘要前600字符及有限标签，标记`evidence_storage=compact_original_with_interpretation_refs`，每条保留interpretation_id；完整正文证据从该解读引用读取，不丢弃、不把展示摘录冒充全文。

如果压缩证据后payload仍超过650000字符，则不再重复嵌入逐篇claims聚合副本，标记claim_storage=news_interpretations；通过每条interpretation_id读取完整主张和引文，已生成的解读文字、分数和独立记录不变，并非丢弃AI结果。普通大小报告保持原结构。评分/解读/报告按账号隔离；部分评分未完成仍不启动正式解读。取消及失败保留已完成分数与逐篇解读，不把展示数量误当成有效结果数。

## 验证

测试覆盖1/25/100输出、候选不足、数量改变复用全库分数、账户偏好隔离、按钮输入及费用取消/确认、探索比例跟随N、100份16000字符正文在报告中压缩而完整证据独立保留。测试不请求真实模型或修改生产数据库。
