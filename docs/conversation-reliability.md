# 对话可靠性与改进入口（2026-10-15）

后续更新：按用户要求，桌面已改为[模型等待不限时](unlimited-model-wait.md)，覆盖下文历史的45秒默认与150/240秒预算。保留错误分类及取消检查，但阻塞等待可能一直持续。

## 排查结论与边界

实际界面检查曾发现：最小请求成功但普通对话失败；非聊天任务结束后聊天页仍显示准备中；重试追加重复卡片。此前的异常处理将多种 HTTPX 传输错误合并为一句“网络失败或超时”，因此无法根据旧提示断言 API、代理还是等待上限有问题。没有取得旧请求底层异常记录，不声称已经证明中转站完全正常或确定每次失败的根因。

离线确认的程序原因：Responses 消息同时保留普通文本/工具调用和原生 output 回放，但旧预算按 dataclass 全量计算，可能重复计数；输出不足/协议错误缺少具体诊断；超时是网络空闲等待而非严格总时限。上述问题不等于所有失败都由程序造成，HTTP 502仍需要上游线路排查。

现场固定探测（不带任何个人上下文，最多3次请求，每次最多1024输出token）：当前已保存连接的基础OK请求HTTP200、约11.05秒；工具回环中，初始固定请求为505字符，失败请求为1023字符、1个工具，90.36秒读取超时。由固定探测的两步结构与请求长度可定位：首次工具请求已返回有效调用，回传echo结果后的第二次请求未及时返回。该结果证明基础入口/凭证可用，并将本次问题缩小到工具回放路径，但不能区分服务端推理耗时、代理/线路还是中转站回放实现。没有再次发送用户兴趣说明，也没有更换模型、协议或代理来掩盖错误。

针对个人档案场景，自动工具模式在候选/确认保存成功后直接生成确定性文字说明，不再为确认保存额外发起模型回放；仅对话及独立兴趣建议模式不需要工具往返。切换模式后点重试，会按当前模式重发原问题并保留草稿，不会暗中继续使用旧模式。通用工具回放仍保留并明确展示失败，不声称当前中转站已通过完整工具兼容性验收。

## 修改与用法

- 安全诊断：区分连接、读取、写入、连接池超时、代理、DNS/TLS/拒绝连接类别、协议中断、HTTP错误、非JSON、非预期事件流、未完成输出。读取错误不再笼统归为网络失败。响应仅读取至4MB；在数据分块间检查取消、任务时限和整次请求等待时限，连接阶段最多10秒。阻塞读取仍需等当前read timeout返回，不能承诺立即取消。
- Responses：不执行 incomplete 中的工具；max_output_tokens 用尽明确标记 output_limit（含推理token），不伪装成网络问题。保持 store:false、stream:false 与原生推理回放，不自动换协议。桌面仅对502/503/504增加一次HTTP恢复尝试，可能增加费用；其他错误不自动重发，详见[gateway-recovery.md](gateway-recovery.md)。事件流回包目前明确报不兼容，不声称支持流式。
- 预算：原生客户端按实际将发送的 JSON 字符计量，原生回放只计算一次；其他实现仍按通用 dataclass 保守估算。没有扩大历史选取范围或自动加入反馈。
- 聊天模式：自动模式保留工具选择；仅对话模式不提供工具，不检索或保存；整理兴趣建议只做一次模型请求，JSON/原话/字段校验后生成个人待确认候选，需用户确认才生效。候选生成失败不自动猜测/保存。
- 请求详情：显示最后一次HTTP请求的安全状态码、阶段、用时、协议、工具数量、请求字符数和当前已生效预算，不展示密钥、正文或服务原始错误。未记录磁盘日志。预算拦截可能发生在下一次HTTP之前，详情会注明最后请求不必等于当前错误。
- 高级设置显示模型等待不限时，不再提供秒数选择；输出额度1800/4096/8192/16384，默认不自动增加。需要更高额度时用户主动选择后重新启用，可能增加费用。
- 连接测试默认只发一次固定OK请求，不验证完整工具兼容性。勾选「连接测试包含工具往返」后最多两次请求，仅使用固定文本和connection_echo，不带账号、兴趣、报告、历史，不调用业务工具。模型未按要求调用不等于已经证明服务不兼容；明确显示尚未确认。输出不足同样报额度错误。
- 重试复用当前失败轮次的用户卡片，替换错误提示，不新增重复消息；仍保留正在编辑的草稿。只影响显示，不删除已保存历史。非聊天任务不再覆写聊天进度；晚到的进度事件被忽略。
- 简报新增「AI重新整理」：使用当前账号已有且通过主题筛选的证据，调用当前模型，另存报告，不重新检索或覆盖旧报告；失败仍可保留来源速览。原始标题latest news显示为“我的关注·自动检索”，日期在阅读卡片中简化，来源原时间不改。
- 反馈新增「讨论这条反馈」：仅将填写或选中的一条反馈转入草稿，由用户确认发送，不自动将私人反馈历史发给模型。来源状态区分已接入尚未检测、本次运行成功/失败和时间，个人状态显示中文；这不是持续健康监测。

## 参考与验证

按 OpenAI Docs 核对[推理输出与未完成响应](https://developers.openai.com/api/docs/guides/reasoning)，按HTTPX官方[异常分类](https://www.python-httpx.org/exceptions/)与[超时定义](https://www.python-httpx.org/advanced/timeouts/)实现传输诊断。对于用户的中转站及模型名，不根据官方模型目录推定其实际能力。

验证以 MockTransport 和虚构数据复现：各类错误隔离、秘密不回显、gzip JSON、意外事件流、输出额度耗尽、真实wire预算去重、工具回环、无工具聊天、候选生成及确认边界、重试显示与任务收尾，以及旧报告非破坏性重整。compileall通过，完整309项测试通过；已渲染中文对话截图。真实用户消息未经明确授权不会用于测试。

时限边界：总响应预算在数据块之间检查；一次阻塞的读取仍需等待read timeout返回，因此不保证墙钟耗时严格等于下拉框数值。response_deadline与read_timeout分开诊断。当前没有后台强杀网络线程、自动跨协议/跨代理重试或宣称所有外部线路问题已解决。
