# 网关错误恢复

后续等待策略更新：桌面模型及外层任务不再设时间上限，详见[模型等待不限时](unlimited-model-wait.md)。下文有限read timeout说明仅适用于显式设置了时间预算的其他调用方；桌面完全阻塞时可能一直等待。

## 目标与使用

重启应用、重新启用连接后，保存的连接和预设连接对502/503/504，以及响应协议中断remote_protocol、接收中断read_error自动重试一次（合计最多两次HTTP尝试），保持同一地址、模型、协议和请求正文。混合故障也共用这两次预算，不层层增加重试。无需修改配置或密钥；进度显示正在重试2/2，请求详情显示attempts。

这只能恢复短暂网关故障，不能修复持续故障的中转站。502不等于密钥错误，也不能单凭状态码确定是哪一层上游出错。若两次都失败，显示状态码、尝试次数及可重试提示，保留草稿。

## 配置、输入输出与边界

create_research_model(gateway_recovery=True)启用桌面恢复策略；其他调用默认仍一次尝试。OpenAICompatibleSettings通过retry_statuses、retry_transport_errors及retry_transport_codes控制范围，桌面分别设为(502,503,504)、False、('remote_protocol','read_error')，max_attempts=2、max_retry_delay=2秒。retry_transport_errors=False禁用广泛传输重试，显式codes只放行白名单中断。连接探测关闭恢复且codes为空，继续遵守基础最多1次/工具回环最多2次请求的测试上限。

传入原消息和工具定义，仅在模型HTTP请求内部重试；不重跑AgentLoop或工具，不重新执行已完成的反馈、档案操作。收到有效模型回复后只处理一次。错误发生前服务商可能已执行生成，因此即使HTTP失败，重发仍可能增加服务商费用；不保证服务端exactly-once。

不自动重发超时、建连/DNS/TLS/代理/写入异常、400/401/403/404/408/429/500、格式错误或未完成输出，不自动切换协议、代理或模型，不修改用户Key。等待依据Retry-After或1秒退避，最多2秒；退避期间每0.1秒检查取消，下一次请求开始前也检查取消。桌面请求不限等待时间，不承诺阻塞中即时取消。断线重试不会把半截响应当成有效JSON。

诊断新增attempts，仅记录数字与固定错误类别，不记录Key、消息、网关响应正文，也不新增持久化日志。

## 验证

使用MockTransport离线模拟502/503/504后成功、持续502、其他状态立即失败、读取超时不重发、取消退避、Retry-After限幅、工具结果回放重试且工具只执行一次，以及工厂配置。所有输入均为虚构测试数据，不使用真实模型额度或个人档案。真实中转站恢复情况需要实际服务验证，不以离线测试替代线上验收。
