# Contextual bandit：兴趣邻域的受控探索

## 它是什么

Contextual bandit（上下文多臂老虎机）每轮读取上下文，选一个动作，只收到被选动作的反馈，再改进后续选择。它不是让LLM随机发挥，也不是必须训练复杂的多步强化学习Agent。未展示的新闻没有反馈；未点击、未评价都保持未知，不作为负例。

对应本项目：

| 要素 | 实现 |
|---|---|
| Context | 已确认兴趣锚点的主题、领域、问题、用途、方法、知识程度，以及全局用途/默认程度的版本摘要 |
| Action | 在同领域、有限概念邻域中的具体候选新闻 |
| Probability | 每个探索位置抽样当时的条件概率；不放回选择 |
| Reward | 用户明确选择“这个方向有用”为1、“这个方向不相关”为0；其他反馈不训练 |

参考[Vowpal Wabbit官方新闻个性化教程](https://vowpalwabbit.org/docs/vowpal_wabbit/python/latest/tutorials/python_Simulating_a_news_personalization_scenario_using_Contextual_Bandits.html)的上下文/动作/概率/反馈接口，不使用其示例的点击率目标，没有安装VW、训练CTR或调用额外模型服务。

## 当前算法和有限能力

主卡片的赞踩/原文打开属于独立[四信号关联性校正](multisignal-ranking.md)，不转换为本模块方向奖励；历史星级也不训练本模块。本模块仅在[分层语义画像](semantic-interest-profile.md)未active且没有大事件/热榜公共名额时兼容使用，防止重复重排或覆盖公共价值。项目已有本地用户兴趣向量更新，但本模块仍是离散策略，不训练QKV。

`recommendation.py`为无网络/数据库/Qt依赖的纯策略模块。现在使用**离散上下文+概念动作特征的平滑奖励估计与softmax选择**，不是LinUCB、神经网络、Thompson sampling或通用语义embedding。多个文章可共享同一锚点下的概念反馈；不同锚点、账号不共享权重。

有限概念邻域来自现有原文提及词表：AI/Agent/LLM/RL/SFT是一组，SSG/凝聚态/群论/投影表示/群上同调是一组。同标签距离0，同组相邻概念距离0.5，其余不允许。只作用于已采集候选，尚未增加基于向量的全网邻域召回；没有认识的标签时不探索。真正多语种embedding的模型/版本/缓存/下载与类内约束由独立语义画像模块管理，不能将本模块离散距离宣传为连续语义向量距离。

## 选择流程

1. 沿用订阅或主动检索、时间/可见性控制、全候选存库与20条一批AI兴趣评分。只有全库完成评分后才选择探索。
2. 默认关闭，完全保留原分数前十。启用后也只对latest news/news/最新新闻等日常关注查询生效；“SSG”等明确检索不做随机拓展，不改变用户问题。
3. N=min(用户指定数量,候选数)，数量1—100、默认10；拓展名额floor(N×epsilon)，其余固定取原始分数前列。例如10条、0.2为8核心+最多2拓展，25条时最多5拓展。
4. 在非核心候选中要求AI原始兴趣分至少40；标题/摘要不得命中明确排除；来源领域必须匹配锚点，或是general补充源；文章概念必须在该锚点允许邻域。用户的方向、排除、知识水平和期限不会被修改。
5. 按局部奖励估计、原始兴趣分和反馈不足的启发式奖励构造效用，在合格候选上softmax采样、不放回。合格邻居不足时用原分数顺序补齐，不放宽门槛，也不假装有拓展。
6. 仅对最终N条执行原有正文阅读和短解读；展示拓展标签与原始兴趣分，不把随机性加到分数上。启用后的列表明确不是纯分数前N。

已确认锚点与局部可学习偏好分开。未确认候选和过期单元不作为新锚点；聊天仍经原确认流程创建长期兴趣。算法不移动锚点向量、不擅自增加大领域，不改变模型语言temperature。

## 参数和公式

在“兴趣与领域→兴趣拓展·可选”设置，点击“保存拓展设置”。每个本机账号独立：

| 参数 | 默认/范围 | 含义 |
|---|---|---|
| enabled | false | 是否启用选择与明确反馈学习 |
| epsilon | 0.2；0—0.3 | 探索名额比例上限；这里不是每条独立的epsilon-greedy抛硬币 |
| temperature | 0.15；0.02—2 | softmax温度，越高越分散；只在已合格邻域中作用 |
| radius | 0.6；0—1 | 当前离散邻域阈值，0仅同概念、0.5起允许同组邻居 |
| learning_rate | 0.15；0.01—0.3 | 反馈敏感度：通过先验强度控制，不是梯度下降步长 |

同一context/tag的有效反馈n条，正反馈之和s，先验强度a=1/learning_rate：

```text
预计有用程度 = (0.5a + s) / (a + n)
效用 = 0.65×AI兴趣分/100 + 0.25×预计有用程度 + 0.1/√(n+1)
P(新闻 | 当前探索位置、剩余合格候选) = softmax(效用/temperature)
```

权重和40分门槛是初始工程设定，不是经过真实用户优化的最佳参数。冷启动预计有用程度为0.5，一次评价受先验约束，不能彻底改变偏好。不确定性项是启发式，不能解释成统计置信区间。学习目前只改变拓展概率，不重排核心推荐、不改AI原始评分，也不触发全库重新调用模型。

## 数据、反馈和隐私

`RecommendationRepository`使用既有SQLite事务与账号权限边界：

- recommendation_settings：账号的参数JSON，不写入YAML或密钥配置。
- recommendation_decisions：报告ID、新闻ID、有界锚点/概念、角色、策略版本、条件概率、当次候选数和是否在卡片列表渲染过；报告也携带这份小元数据。不保存未入选整库的概率表、逐条筛选理由或模型推理。
- recommendation_feedback：每个账号/报告/新闻最多一个明确奖励，修改为替换，撤回即删除；不因重复点击或重开报告重复学习。统计时同一context/tag/evidence_id跨报告去重，用最近反馈。最多聚合最近5000条显式反馈。

ResearchSession保存报告后登记选择计划；生成不等于展示。桌面渲染当前栏目卡片后标记displayed，表示列入界面而非保证用户读过；只有实际选择明确反馈才产生奖励。服务层拒绝跨账号报告、未展示条目、核心条目和未知类型反馈。旧报告没有选择记录，不追认其历史星级为训练数据。

在简报“评分”页，拓展条目有独立下拉：“不参与学习/撤回”“这个方向有用”“这个方向不相关”。人工1—5分仍是独立评价，不训练此策略。太难、重复、来源问题、今天不看等仍走原反馈分因流程，不当成主题负例。聊天record_feedback目前不关联具体拓展选择，因此不自动训练这里的奖励。

关闭后不再探索或学习新正负反馈；仍可撤回旧反馈，或在设置中确认“清除拓展学习”，删除本账号反馈，不删新闻、档案、决策和人工星级。重新开启后保留的旧反馈仍有效。画像锚点/用途/程度改变会改变上下文键，旧反馈不会错误作用于新锚点。共享信源不共享学习记录。

## 错误与兼容

参数拒绝非数值、NaN、无穷和越界；旧账号默认关闭。无模型、未完成评分、空结果没有随机排名。没有邻域时回退原前N，只对用户指定数量解读；策略本身0次额外LLM或搜索调用，增大N会增加阅读/解读费用，超过10条桌面确认。取消/正文失败仍保留原分数与已完成内容。历史不因反馈自动改写，下一次生成应用新概率；重新整理按选定数量另存，可重新抽样。

概率是**逐位置、给定前面选择的条件概率**，核心位置记1不是所有文章进入整份列表的边际概率。目录只保存候选数而非完整候选快照；确定性核心没有完整策略覆盖，不能据此声称能无偏评估任意新策略或直接做整列表IPS。当前没有上线反事实评测、真实用户A/B，也没有证明消除了信息茧房。

## 验证

`tests/unit/test_contextual_exploration.py`使用固定种子/假模型验证：参数、温度分散性、邻域/领域/排除/过期、默认和显式查询不变、配额和不放回概率、正负反馈改变选择概率、无反馈不学习、重复/修改/撤回/清除、账号隔离、原分数保留、最终最多10份解读及Qt设置持久化。完整compileall/pytest结果见独立时间命名记录。离线模拟仅证明行为，不等于真实推荐质量提升。
